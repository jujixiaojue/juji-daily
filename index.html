🤖 AI Agent 前沿洞察

Google Workspace：官方 MCP 服务器与 CLI 全面可用，并设定智能体接入门槛

11 月 24 日，Google Workspace 产品博客与 Workspace Updates 同步宣布：Workspace 的官方 Model Context Protocol（MCP）服务器与 CLI 正式全面可用（Generally Available），作为智能体访问 Workspace 数据的「默认前门」。官方说明称，MCP 服务器面向云端与网页智能体，可开箱使用 Gmail、Google Drive、Docs、Sheets、Slides、Calendar、Chat 和 Tasks（Keep 即将加入）；CLI 面向本地与桌面智能体及工作流自动化，提供范围受限的登录与 IT 治理。

同一公告给出治理安排：新的 Workspace AI Tools Addendum 要求智能体通过 MCP 或 CLI 接入，而不是传统 REST API，技术强制执行自 2027 年 2 月 1 日开始。外部智能体须使用专用 OAuth 客户端 ID，配合最小权限范围；用量配额的计费自 2027 年 4 月 1 日开始。发送外部邮件、更改 Drive 共享权限或进行批量编辑等影响较大的操作，需按 IT 策略取得用户确认。管理员可在管理控制台查看、审计和撤销智能体；用户侧查看活动与撤销权限的能力官方写明为即将推出。

来源：Google Workspace 产品博客（2026-11-24）；Google Workspace Updates（2026-11-24）；Google Cloud 安全博客（2026-11-24）；开发者参考：workspacemcp.googleapis.com。

OpenAI：GPT-6 系列展示蛋白质设计能力，湿实验给出可核对的结合率

OpenAI 于 11 月 24 日发布研究文章，并附预印本《GPT-6 as a Universal Foundation Model for Protein Biology: Beyond Specialized Models》。文中称，GPT-6 系列可在不调用专用生物学模型的前提下，仅靠推理与通用编程工具设计新的蛋白质三维结构与氨基酸序列；在多项计算评测中，内部研究模型达到或超过专用模型，但「预测完整蛋白质结构」仍是明确短板。

湿实验与合作方 Onava 完成，需把「结构由通用模型设计」与「管线中仍使用专用模型」分开看。实验一：由预发布版 GPT-6.2 设计三维结构，专用模型提供氨基酸序列并协助筛选候选；实验室共测试 322 个 minibinder、覆盖 5 个靶点，其中 35 个（10.9%）对预定靶点呈结合阳性（PD-L1 5 个、IL-7Rα 3 个、TrkA 1 个、VEGF-A 8 个、IL-17A 18 个）。官方同时写明，RFdiffusion 原研究曾报告更高命中率，而命中率高度依赖于送检前的筛选尺度和结合的定义。实验二则让 GPT-6.2 在给定三维配合结构、隐藏原始序列的条件下重写序列：MDM2 为 75/88（85%）、VEGF-A 为 26/42（62%）、PD-1 为 8/59（14%）；对模型自生成、此前未发表的结构，107 条新序列中有 14 条（13.1%）显示结合。这是通用大模型蛋白质设计的实验室结果，并非已上市药物或临床试验数据。

来源：OpenAI 研究文章（2026-11-24）。

Anthropic：Claude Artifacts 可在 Mac / Windows 上安装为独立应用

Anthropic 在 Claude 帮助与产品文档中宣布，「Install as app」功能以测试版在 Claude for Mac 和 Windows 中推出：把常用 Artifact 安装后，可拥有独立图标并在独立窗口中打开，而不再只存在于 Claude 会话里。安装后的应用可使用 Claude 与用户已授权的连接器，并在底层 Artifact 被编辑后自动更新；向 Claude 发出的请求计入所属方案的用量上限。用户无需自行打包或签名，也无需单独的 API 密钥，但需要保持在线并登录 Claude 才能打开。

权限分为三档：默认（仅相当于浏览器内可做的事）、应用权限（通知、全局快捷键、置顶窗口等受控能力），以及完整计算机访问（可在未逐次询问的情况下运行程序、读写或删除文件）。完整访问仅适用于用户自己制作的应用，或 Team / Enterprise 中由本组织人员制作的应用；每次更新后（包括用户自己的编辑）都会重新询问权限。官方写明 Anthropic 不会在安装前审查这些应用。HIPAA-ready 组织与混合部署不可使用该功能；Team 默认开启但关闭完整访问，Enterprise 需由所有者打开后才可用。

来源：Claude 官方说明：Turn artifacts into Mac and Windows apps；报道参见 MacRumors（2026-11-25）。

未来方向洞察：今日几条主线指向同一件事：智能体正在从「会对话的助手」变成「要登录工作区、要写文件、要改共享权限、甚至要设计分子」的执行者。Google 把 MCP/CLI 做成企业前门并给出强制时间表，说明治理已经从原则走到接口层；Claude 把 Artifact 做成可安装的桌面应用，则把「产物」变成「常驻工具」。与此同时，蛋白质设计的湿实验提醒我们：通用模型开始进入需要实验室验证的科学工作流，但命中率、筛选标准和专用模型是否仍在环内，都必须写进结论里，而不能只看标题。对做 Agent / 本体中台的团队，接下来更关键的可能不是再多一个聊天入口，而是：动作走哪条官方通道、权限如何按对象回收、以及执行结果如何被独立验证。

🧬 Ontology（本体）生态动态

Google 将 Workspace 权限、DLP 与分类标签接到智能体的每一次调用

Workspace 官方 MCP / CLI 的治理设计，对本体中台有直接对照价值：官方称每一次调用都会对照组织的 Workspace 权限、数据丢失防护（DLP）规则和分类标签；附件还禁止将智能体用于持久化原始存储或模型训练，并要求在断开连接时删除相关数据、在限定窗口内清除派生数据。这意味着「对象、权限和动作」被放到了协议层，而不只是写在提示词里。技术强制执行日期为 2027 年 2 月 1 日，给现有直接调用 REST API 的集成留下迁移窗口。

⚙️ Agent Harness、运行架构与新技术

a / f) 执行架构与运行质量：把策略检查放到每一次工具调用上

Google Cloud 与 Workspace 的配套博客写明：在 Workspace 侧，AI Tools Addendum 要求智能体走 MCP 或 CLI，每次调用对照权限、DLP 和分类标签；在 Google Cloud 侧，Agent Gateway 在协议层执行 IAM 与默认拒绝的出站规则，并可通过 Service Extensions 把自定义检查路由到 Identity-Aware Proxy、自有策略引擎或第三方安全工具。智能体在 Agent Registry 中拥有独立的 Agent Identity，不使用共享或长期密钥。高影响动作（发送邮件、修改共享、变更 IAM 或生产基础设施）可被要求经过人的确认或多因素验证。这是一套已公布时间表的运行质量方案：可观测、可撤销、可按身份限额。

来源：Google Cloud 博客（2026-11-24）。

e / c) 能力扩展与上下文：HyperHarness 从用户历史生成个性化运行框架

论文 HyperHarness: Learning to Generate Personalized Agent Harnesses from User Histories（arXiv:2611.29062，提交于 2026 年 11 月 21 日）提出：与其为每个用户单独搜索一套提示或工作流，不如训练一个可复用的「历史 → Harness」生成器，直接根据用户历史合成可执行的检索与答题引导代码。作者在 MemoryCD 上用 Qwen3.5-9B、覆盖 223 名用户和 2,676 次请求的对照中报告：生成式检索把答题时的平均 token 从长上下文的 32.51k 降至 3.15k（降低 90.32%），同时保持相当的任务分数。在成本曲线上，该方法先支付一次共享训练代价，再对每个用户做一次轻量构建；论文称在大约 9–35 名用户之后，累计代价可低于按用户反复搜索的基线。这是可复现的研究实现（以论文与代码声明为准），尚不是某一家主流产品的正式发布说明。

来源：arXiv:2611.29062（2026-11-21）。

🧠 Agent 记忆、企业知识与本体驱动执行

a / b) 记忆与企业知识：用历史生成规则，而不是把全部记录塞进上下文

HyperHarness 把「个人记忆」做成可执行的检索与答题规则：模型不是在每次提问时重读全部历史，而是先从历史中归纳出该用户适用的检索程序。论文还比较了「缺少证据」与「被无关文本干扰」：在部分数据集上，注入干扰项比删除同等记录伤害更大。这对组织记忆的启示是：更新和遗忘不仅是存档策略，也是过滤误导性记录的问题。

来源：arXiv:2611.29062。

c / d) 动态知识到行动：对象、标签、权限，先于模型自由发挥

Workspace 的设计把邮件、文件、日历和任务视为可被调用的对象，并把共享权限变更、外部发送和批量编辑设为必须确认的动作；分类标签与 DLP 在每次请求时生效。Neo4j Context Engine 的官方表述则是：在决策与行动点提供经治理的业务上下文，并且「用得越多越好」。两者都在回答同一问题：智能体根据哪些对象、关系和规则选择动作，以及这些依据能否被撤回。

来源：Google Workspace 博客；Neo4j Context Engine 博客。

e) 可信交互：确认、引用限制，以及实验室里的「阳性」定义

Claude 安装应用要求完整访问仅授予来源可信的应用，并在每次更新后重新授权；Google 则把确认、审计和撤销放进管理控制台。OpenAI 的蛋白质实验提供了另一种可信性样本：它同时公布命中率、各靶点计数，并主动写明专用模型的角色以及与 RFdiffusion 命中率不可直接对比的原因。对本体驱动执行来说，可信性不只是「给出链接」，还包括说明管线里还有谁、筛掉了什么、以及阳性意味着什么。
