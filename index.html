🤖 AI Agent 前沿洞察

DeepMind：用多组 Gemini 4 Agent 与 Lean 证明改进量子算法

Google DeepMind 于 11 月 23 日发布博客 Finding faster quantum algorithms with agents and formal verification，介绍其与 Google Quantum AI 的合作：为每个问题安排彼此独立的 Gemini 4 Agent 团队寻找算法改进，想法须先通过 Lean 形式化验证，再写入共享笔记；每 4 小时，不同团队的 Agent 在虚拟讨论中交换与比较想法。官方给出的成本（量子比特与操作的综合度量）结果包括：惯性约束聚变模拟下降 11.8 倍，逻辑量子比特需求由 5,650 降至 4,338；某光敏分子模拟成本下降 8 倍；药物代谢酶细胞色素 P450 模拟改进 2.5 倍，量子比特由 481 降至 333；对 Grover 算法的某一实现给出 2.57 倍加速；对用于把数值载入量子态的 arcsin 例程给出 290 倍加速。作者同时写明：即便经过这些改进，相关科学模拟所需资源仍可能超过第一代纠错量子计算机可能提供的能力。团队开源了 Lean 量子算法库、问题规约与已验证题解。

后续报道指出，博客中的部分数字与论文正文不完全一致（例如聚变一项，博客为 11.8 倍，论文正文另有 10.9 倍等表述）。下文以官方博客数字为准，引用论文时需核对原文。

来源：Google DeepMind 官方博客（2026-11-23）

Anthropic 推出 Claude Ship：审查、修复并按策略批准拉取请求

Anthropic 于 11 月 23 日宣布 Claude Ship 进入测试版。产品由已正式提供的 Code Review，以及两个测试版组件组成：PR Steward 负责在持续集成失败、合并冲突和审查意见之后让拉取请求保持可合并，但被设计为不批准、不合并；Claude Approvals 则读取仓库中由团队编写的策略文件，对符合政策的常规变更予以批准，或要求更深入的人工签核。开发者可在 Claude Code 中使用 /ship 命令推送变更、打开拉取请求并跟进修复；管理员也可按仓库开启自动流程，并设置审查深度与支出上限。官方建议多数客户先以观察模式运行批准策略。符合条件的 Claude Enterprise 组织可在领取后 30 天内使用至少 10,000 美元的 Claude Ship 额度，领取截止时间为 2027 年 1 月 15 日（条款适用）。

来源：Anthropic《Introducing Claude Ship》（2026-11-23）

OpenAI 与 Cisco 开源 Shirudo：在补丁落地前为运行中的 Linux 系统加「盾」

OpenAI 与 Cisco 于 11 月 23 日宣布开源运行时 Shirudo（日语「盾」之意）。项目基于 eBPF，目的是在正式补丁测试与部署仍需数日或数周时，先对正在运行的 Linux 系统施加可撤销的临时防护，而不必重启服务。官方介绍四项能力：在线防护、由 Agent 协助调查漏洞并生成盾牌、盾牌在加载前经密码学签名校验，以及借助 TPM 留下可验证记录。OpenAI 称，在一次受控测试中，由 Codex 生成的盾牌在无需重启的情况下，阻断了针对运行中 Elasticsearch 服务的 Java4Shell 利用尝试。代码仓库为 github.com/shirudo-dev/shirudo。官方同时强调：盾牌是否启用仍由安全团队决定。

来源：OpenAI《OpenAI and Cisco introduce Shirudo》（2026-11-23）；Cisco 新闻稿

未来方向洞察：过去 72 小时里，Agent 被放到了三种很不一样的「可检验闭环」里。DeepMind 让多组 Agent 分工搜索，但只有通过 Lean 证明的改进才能进入共享知识；Claude Ship 把审查、修复和批准拆成可配置策略，并明确建议先观察再接入分支保护；Shirudo 则允许 Agent 起草针对运行系统的临时防护，但加载前要签名，最终是否生效仍由运营者批准。对做 Agent / 本体中台的团队，这提示同一趋势：规划与工具调用已经足够强，真正被产品化的是「谁有权让结果生效」以及「生效前用什么规则来证明它是对的」。

🧬 Ontology（本体）生态动态

AutoOntologyBench：用真实任务检验「Agent 能否构建有用的本体」

arXiv 论文 AutoOntologyBench: A Task-Grounded Benchmark for Agentic Knowledge Engineering（编号 2611.27734）于 11 月 20 日提交，作者来自杜伦大学、上海财经大学、北京协和医学院 / 北京协和医院，以及阿里巴巴达摩院。摘要提出的问题是：基础模型 Agent 正从软件工程扩展到自主科研，工业界也越来越多用知识图谱和基于本体的语义层来组织异构知识；那么，自主 Agent 能否构建有助于完成真实任务的本体，这些本体相对其他知识表示是否有可测量的收益？现有基准往往停在「能不能写出本体」，这篇工作则强调以任务为落地检验。对关注本体中台与 Agent 问数的团队，这是一份可直接对照评测设计的公开材料，具体数据集划分与分数需读全文后引用。

来源：arXiv:2611.27734（提交于 2026-11-20）

Palantir：建造企业用本体关联数据微调小模型；AIP 在英国上架 Gemini 4 Argon

Palantir 官方账号于 11 月 19 日介绍 DevCon 7 上 McCarthy Building Companies 的案例：在本体关联数据、Model Studio、GPU Hubs 与 AIP Evals 组成的「主权模型工厂」上，将建造领域经验微调到约 40 亿参数的小模型。帖文称，该模型在其评估集上达到约 73% 的平衡准确率，对照领先前沿模型 Astra 的约 62%，误报减少约 20%，成本为前者的一小部分。这是企业侧「用本体约束的领域数据训练小模型」的公开案例，评估集由展示方提供，外推需谨慎。另据 Palantir 11 月文档，Gemini 4 Argon 已可通过 Google Vertex AI 在 AIP 中用于英国地理限制的商业租户，推理运行在伦敦。

来源：Palantir 官方账号（2026-11-19）；Palantir Foundry 2026 年 11 月公告

微软 Foundry IQ 知识图谱仍在落地，本周工程笔记补充了数字

微软于 11 月 17 日将 Azure AI Search 以 Foundry IQ 为名，把知识图谱作为面向 Agent 的检索能力（详见 11 月 24 日早报）。Geert Baeke 11 月 23 日的技术笔记补充了微软自身评估中的若干数字：在针对 SEC 文件的六类问题上，实体图正确率报为 93.5%，对照普通 RAG 的 26.1%，并称少用 64.3% 的 token；在主题类问题上，Topics 图比向量检索的证据召回高 7.8 个百分点（71.2% 至 79.1%）。笔记同时提醒：知识图谱仍为公开预览，部分数字来自微软自己的评估，部分题类样本量较小； refined ontology 比自动生成的起点多抽出 40% 的不同事实，说明本体设计本身会影响答案质量。

来源：baeke.info 技术笔记（2026-11-23）；微软 Foundry IQ / GraphRAG 官方材料见 11 月 24 日早报

e / f) 能力扩展与运行质量：自我改进的 Harness，以及 Shirudo 的加载控制

arXiv 论文 Harnesses That Improve Themselves: A Unifying Framework for Self-Improving Agent Harnesses（2611.22299）于 11 月 17 日提交。作者把 Agent Harness 定义为把单步 token 预测变成长程多轮执行的有状态运行时，并拆成四块可编辑组件：上下文与状态、Agent 控制、动作接口、验证与恢复。外层再加四阶段循环：诊断失败、提出对 Harness 代码的补丁、在运行与留出集上验证、再部署。论文强调，整份 Harness 重写容易过拟合或破坏模块，带验证门的模块化更新能在不同模型间更好泛化并控制 token 成本；同时讨论提示膨胀、刷榜和篡改评估器等自我修改风险。作者称在 SWE-bench Lite 上验证了这一框架。这是可公开复核的研究框架，是否已有生产级采用需另行考察。

Shirudo 则给出运行质量的另一面：Agent 可以起草防护，但盾牌须签名、经 eBPF 验证器检查，并由运营者决定是否加载；TPM 留下可审计记录。这与 Claude Ship「先观察、再把批准纳入分支保护」是同一类工程选择。

b / c) 长任务与上下文：Claude Ship 把失败检查变成可恢复的后续步骤

PR Steward 被设计为在每次推送之后说明改了什么、如何撤销，并在 CI 失败、冲突和审查意见出现时继续工作，而不是一次性跑完。这是一种把「长任务」放回原有 Git 工作流的做法：状态在拉取请求和检查记录里，而不是只在对话窗口中。Glean 的实时邮件触发则把等待从轮询改成事件到达即启动，减少长任务在「等下一封邮件」时的空转。二者都还没有在公开文档中展开通用的检查点或跨会话恢复协议，但对于办公与研发场景，现有系统的事件、PR 和评论正在被当作 Harness 的外部状态层来用。
