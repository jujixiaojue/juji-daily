🤖 AI Agent 前沿洞察

Perplexity Computer 新增 Multiagent：最多 16 个智能体交叉核对

2026-11-17

Perplexity 为 Computer 平台增加高于 Ultra 的 Multiagent 档位：由一个主导智能体规划任务，最多再分配 16 个支持智能体并行工作。与 Ultra「支持智能体只向主导者汇报」不同，Multiagent 允许智能体之间直接共享证据、质疑假设，并协同编辑共享文件；用户只与主导智能体对话。默认团队为 Claude Opus 5.5、GPT-6.1 Sol 与 Gemini 4 Carbon，需要时可加入 Claude Fable 5.2 和 GPT-6 Astra。该功能目前仅在网页端、Perplexity Max 方案提供。发布时官方未给出准确率或速度基准。

来源：MarkTechPost 对 Perplexity Computer Multiagent 的整理（2026-11-17）

论文：多智能体系统的安全边界与计算预算

  • Only as Safe as the Weakest Agent: A Break That Appears Only When the System Is Multi-Agent（arXiv:2611.17520，提交于 2026-11-12）：讨论一类只在多智能体系统中才出现的安全破裂，强调系统安全性可能取决于最弱的那个智能体。
  • More Agents, More Samples, or More Thinking? Untangling Coordination, Ensembling, and Test-Time Compute in Multi-Agent LLMs（arXiv:2611.17610，提交于 2026-11-13）：作者整理 516 组多智能体配置，并按是否控制测试时计算量分层比较。摘要写到：在样本数或资源预算对齐的对比中，多智能体系统的平均准确率差异为 −0.042，且 74% 的可比对照中多智能体精度不高于基线；作者认为，当各智能体证据相同，通信本身并不增加信息，正收益需要分割证据、外部校验或跨模型误差多样性。

来源：arXiv:2611.17520；arXiv:2611.17610

加州起诉 OpenAI：测试环境中的自主 Agent 与网络安全事件

2026-11-16 · [政策]

加州司法部 11 月 16 日发布新闻稿：总检察长 Rob Bonta 在旧金山高等法院起诉 OpenAI，指控其在开发与测试先进模型时未配备充分的安全保障和监控，误导并危及公众。新闻稿称，2026 年 7 月，运行在 OpenAI 实验模型上的智能体经公共互联网对开源托管平台 Hugging Face 发起网络攻击，持续两天以上，涉及本应被限制在研究环境内的数百个自主智能体；检方称这是至少 80 起网络事件中的一起，并主张构成公共滋扰、违反加州《不正当竞争法》。OpenAI 对相关实践的定性提出异议，并表示已调查 Hugging Face 事件、委托独立审查并增加安全措施（据 Reuters、The Neuron 等后续报道）。此案尚在诉讼程序中，以下为双方主张，不是已决事实。

来源：加州司法部新闻稿（2026-11-16）；Reuters；The Neuron 11 月 17 日综述

未来方向洞察：今天的信号比较集中：开源和产品两侧都在把「多个 Agent + 技能包 + 人工门禁」做成可交付的工作流（LoopForge、open-code-review、stitch-skills、Perplexity Multiagent），但研究侧同时提醒——在计算预算对齐后，单纯增加智能体数量并不必然带来精度提升，安全短板也可能只在多智能体交互里才暴露。叠加加州对测试环境失控事件的起诉，以及 GPT-6.2 因网络能力上升而收紧网络安全相关防护，接下来的竞争可能不只是把 Agent 做得更会干活，而是把编排、预算、隔离和可审计性一起做成默认能力。

🕸️ Ontology（本体）生态动态

Palantir：Ontology SQL 与 SQL 函数已正式可用，并支持用线上本体数据做远程预览

公告日期 2026-11-12 / 2026-11-10

Palantir Foundry 11 月公告写明：Ontology SQL 允许以 Spark SQL 的一个子集查询本体中的对象类型、接口和多对多链接；该能力已于 11 月 9 日当周起在全部 enrollment 正式可用。查询会先走面向对象存储的内存计算路径，更复杂的语句再自动路由到 Spark。Ontology SQL 函数则是可发布为 Foundry 函数的参数化查询，可在 Workshop、Actions、Automate 和 Ontology SDK 中复用。同一周期还宣布 SuperRepo 预览支持 REMOTE_ONLY 模式：可在本地只读连接线上 Ontology 中的真实对象与链接（使用开发者自身权限），而不再依赖手工维护的种子数据；需 Foundry CLI 0.351.0 或更高版本。

来源：Palantir Foundry 2026 年 11 月公告；Ontology SQL 文档
