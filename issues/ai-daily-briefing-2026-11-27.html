🤖 AI Agent 前沿洞察

Anthropic：用生产流量做校验器，将 Messages API 从 Python 迁到 Rust

11 月 25 日，Anthropic 发布工程文章 Migrating our Messages API to Rust。Messages API 是客户以及 Claude Code、Cowork 等自家应用访问 Claude 的主要接口。文中称，自 2024 年初至 2026 年秋，该 API 流量约增长 1,800 倍。Claude 约用一周写出核心请求路径的首个 Rust 版本；但真正的瓶颈是校验：Python 服务在迁移期间仍在变更，模型输出具有非确定性，且工程团队不能直接阅读客户请求。

官方做法是把仍在线上的 Python API 当作「正确性」来源，对生产流量做对照（shadowing），按差异出现的步骤、位置和长度形成指纹并归组，再自动派发 Agent 修复。文中给出一个关键对照：2026 年 4 月，Rust 版本测试通过率约 98%，但在生产流量上只有约四分之一的输入与 Python 一致——测试未覆盖的细节（例如工具调用 JSON 里 emoji 的转义方式）会在真实请求中被反复放大。CPU 数字来自单一区域，首 token 时延来自客户 Claude Code 请求的较短窗口。最终，官方称迁到 Rust 后每请求 CPU 约降低 70%，首 token 中位时延约降低 20%，且未中断服务、也未冻结功能开发；面向公众的流量在 2026 年 9 月切到 Rust。

来源：Anthropic 工程文章（2026-11-25）。

OpenClaw Foundation：ShellBench 显示头部 Agent 日常任务通过率约六成

OpenClaw Foundation 于 11 月 24 日发布 ShellBench，并同时挂出论文预印本（arXiv:2611.32946）。评测与 Parsewave、Hugging Face、Red Hat、加州大学伯克利分校的研究者合作，从超过 1,000 万条匿名真实智能体交互中归纳出 100 项日常任务（如对账、核对过期说明、整理邮件与收据），工作区文件数中位数为 188。评测覆盖 12 个模型、5 种 Agent Harness（Claude Code、Codex、Hermes、OpenClaw、Pi）和三档推理力度，共 53,100 次评分运行。

按各 Harness 平均，通过率最高的是 GPT-6 Astra（62.5%）、Claude Fable 5.2（61.9%）和 GPT-6.1 Sol（61.4%），前三名只差 1.1 个百分点，也就是最好成绩仍会在约四成尝试中漏掉某项要求。可靠性更低：Astra 在三次尝试中至少成功一次的任务占 75.1%，但三次全部成功的只有 48.8%。官方按记录到的 token 用量和研究所用单价估算（不含评分成本）：Astra 每次约 1.10 美元，Fable 5.2 约 0.83 美元，Sol 约 0.19 美元，即 Sol 以约六分之一的费用接近最高通过率。

安全方面，53,100 次运行中有 15.7% 至少未通过一项安全检查；在全部正确性标准都满足的 26,151 次运行里，仍有 2,589 次（9.9%）未满足安全要求。换模型带来的通过率差距中位数为 45.7 个百分点，换 Harness 仅为 6.2 个百分点；但 Harness 仍会改变 token 用量、改写次数和完成时间。这些是该基金会在自有任务集上的结果，不是跨全部办公场景的定论。

来源：OpenClaw 博客（2026-11-24）；论文：arXiv:2611.32946。

Cloudflare：Search for Agents 把站点检索做成智能体可发现的标准入口

Cloudflare 于 11 月 25 日宣布 Search for Agents：在控制台为某个站点打开开关后，系统会自动创建 AI Search 实例、开始索引内容，并在该域名下暴露检索接口。智能体可通过页面中的 agent:endpoint 等元数据，或（在已开启 Markdown for Agents 时）通过 Markdown 的 YAML 头发现地址，然后向 https://example.com/.well-known/search?q=... 发送 GET 或 HTTP QUERY 请求。返回的是相关内容的 Markdown，而不是由检索服务生成的最终答案，以便智能体再用自己的模型处理。

官方写明该功能对所有方案开放（含 Free，但有额度限制），用量受 AI Search 定价与方案限额约束，并仍受该域名的机器人管理、AI Crawl Control 和 WAF 等设置影响。这是一种「站点自己提供检索入口」的集成方式，不是通用搜索引擎替代品。

来源：Cloudflare 博客（2026-11-25）；Cloudflare Changelog。

未来方向洞察：今天几条消息指向同一个工程问题：生成已经很快，难的是可重复的校验和可发现的接口。Anthropic 把旧系统当成校验器，用指纹归组差异再派 Agent 修复，说明「长任务能否交付」取决于有没有机械、持续的对错信号。ShellBench 则给出另一面：最好的模型在杂乱办公任务上大约六成通过，一次成功并不等于三次都成功，而且正确完成也不等于通过安全检查。Cloudflare 把检索收成域名下的标准入口，则是在降低智能体靠爬页猜内容的成本。对 Agent / 本体中台来说，下一阶段更可能比的是：对象和权限能否被调用、结果能否被对照、失败能否被归类，而不是再多一个聊天窗口。

📚 Ontology（本体）生态动态

站点知识开始被写成智能体可调用的对象，而不只是待爬页面

Cloudflare Search for Agents 的设计，把「网站上有哪些可引用的文档」做成带发现元数据的检索对象：智能体先发现端点，再按关键词或自然语言取回 Markdown 片段，并自己决定如何引用。这对本体中台的启示不是又多了一种爬虫协议，而是知识提供方开始规定：哪些内容可以被检索、以什么格式返回、以及仍受哪些访问控制约束。

来源：Cloudflare 博客（2026-11-25）。

ShellBench：引用依据被写成可评分的任务要求

ShellBench 官方说明称，在 77 项任务中有 87 条评分标准检查答案是否点名所使用的文件，包括用于裁定冲突信息的记录。这把「知识从哪里来」从写作风格改成了任务是否完成的一部分，与本体驱动执行里「先给出对象和出处，再执行动作」是同一类约束，只是评测场景是办公文件而不是企业对象目录。

产业观察 《European Biotechnology》：AI 制药的瓶颈正在转向可训练的实验室数据

该刊 11 月 23 日的长篇观察提出：对部分药企和 AI 制药公司而言，实验室产出的标准化扰动数据本身正在成为可交易的产品，而不只是某一候选分子的副产品。文中举例：Roche 与 Genentech 曾两次向 Recursion 各支付 3,000 万美元，以换取大规模生物学数据集，两次付款都不附带一个药物；今年 7 月，GSK 同意向 Relation Therapeutics 支付最高 1.10 亿美元，用于类似的数据驱动合作。Recursion 已交付六份基于图像的「phenomap」；其中两份覆盖神经科学全基因组，一份来自公司自制的万亿量级 iPSC 来源神经元细胞子集，另一份来自超过 1,000 亿个小胶质细胞和 4,600 万张图像。文中写明，Genentech 在 2026 年 8 月行使期权，将第一个神经科学靶点推进到早期发现。

文章同时给出需要分开看的口径：早期 AI 制药公司曾加快产生候选分子，但 Exscientia 的首个候选在 I 期后终止，BenevolentAI 的领先项目在 IIa 期未能优于安慰剂；作者写到「截至今日，尚无 AI 设计的药物上市」。这不是对全部管线的判决，而是提醒：计算设计、湿实验数据生产、临床试验和上市审批是不同阶段。文中还转述 Relation 首席执行官 David Roblin 的说法：实验不再只为回答单个生物学问题，而是为了让模型学习生物学的底层规则；因此记录条件、对照和扰动的元数据成为实验的一部分。

⚙️ Agent Harness、运行架构与新技术

a / f) 执行与运行质量：把旧系统变成校验器，而不是只靠测试套件

Anthropic 的 Rust 迁移给出一套可复核的运行架构：先定义「与生产 API 行为一致」为正确，再在请求路径上设置检查点，对输入与输出分别对照，用指纹归组同一类差异，然后派 Agent 修复并由人审核合并。4 月时测试通过率与生产一致性的巨大落差，说明测试套件会过早宣布「快完成了」。对中台的直接含义是：规划、工具调用和动态调整之后，还需要一个不依赖阅读客户原文也能工作的差异信号，以及可审计的修复闭环。官方写明，工程师逐步从内层循环退到规则和审核，公众流量在 9 月切换。

b / e) 长任务与能力扩展：评测显示模型仍比 Harness 更能决定日常任务成败

ShellBench 在五种主流 Harness 上跑同一批杂乱办公任务，结论并不是「换一个运行框架就能跨过可靠性门槛」。换模型的通过率差距中位数是 45.7 个百分点，换 Harness 是 6.2；头部五模型里，两个差距分别收窄到 15.2 和 9.9。Harness 仍然影响耗时、token 和改写次数，也对安全通过率几乎没有整体拉开。三次运行中「至少一次成功」与「三次都成功」的落差，则直接对应长任务里的失败重试：能做完一次，不等于可以交给无人值守的循环。

来源：OpenClaw 博客；arXiv:2611.32946。

c / d) 上下文与协作：可发现的检索端点，以及仿真里留下的技能文件

Cloudflare 把站点检索做成 /.well-known/search，是一种无需为每个 Agent 单独集成的上下文获取方式：返回片段而不是最终答案，权限仍留在站点设置里。AA-Robotics-Sim 则要求模型在练习阶段只把笔记、代码和技能写成文件，评估时从这些文件的副本起步——这是把上下文和可复用工作流显式落到文件系统，而不是依赖一次会话的长上下文。二者都已有公开说明或可复核的评测协议，前者已在 Cloudflare 网络上线，后者仍是仿真研究预览。

🧠 Agent 记忆、企业知识与本体驱动执行

a / b) 记忆机制：个人记忆随账号走，团队记忆被写成共享工作区

Claude Duet 明确使用同一 Claude 账号里已有的记忆、技能和连接器，并从第一条消息起就在同一线程中延续，而不再另外「开一个新机器人」。MyClaw 3.0 的产品叙述则把多枚「队友」放在共享记忆和托管电脑上，经即时通讯渠道接收定期任务。两者都还不是完整的组织记忆系统：Duet 目前不对 Team / Enterprise 开放，MyClaw 的共享记忆范围和遗忘策略需看官方文档再核对。

来源：Claude Duet 产品页；MyClaw 3.0 发布概述。

c / d) 动态知识到行动：先批准，再执行；先有可训练的记录，再谈模型

Duet 把发送消息、付款等动作设为必须确认，并在用户自己的云电脑中处理登录与安全检查。这是「根据对象和权限选择动作」的一种产品实现，依据是连接器里的邮件、日历、支付和文档，而不是自由发挥。制药行业的观察则提供了另一类动态知识：Relation 等公司把扰动实验的元数据视为模型学习的前提——条件记录不一致，模型就会把操作噪声当成生物学效应。对本体驱动执行来说，对象状态的更新和实验/业务记录的一致性，决定了智能体能不能选对下一步。

来源：Claude Duet 产品页；European Biotechnology（2026-11-23）。

e) 可信交互：点名依据，并承认一次成功不够

ShellBench 把「是否写出所用文件、如何处理冲突记录」写成评分标准，并把安全检查从正确性里单独拆出：任务做对了，仍可能在授权或信息可信度上失败。Anthropic 的迁移文章则展示了另一种可信性：不能阅读客户请求时，仍然用对照、指纹和人工审核来解释「我们改对了什么」。对本体中台，可信交互不只是附上链接，还包括说明筛掉了什么、哪一次运行不能外推到每一次运行。
