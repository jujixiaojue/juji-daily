1. 导读

要分清两层。Palantir 自己的 Ontology MCP（OMCP）怎么暴露能力；以及自家方案里，图数据库、推理机、对象集各管什么。后者才是要落地的契约。

2. Palantir OMCP 暴露什么

Palantir OMCP 暴露：对已暴露类型的 SQL 查询（Ontology SQL）；Action types、query functions，以及经 AIP Logic 的 Agents。支柱仍是数据、逻辑、动作、安全。语义搜索 / KNN / AIP 可用于检索，但不等于「图推理替代了问数」。

3. 自家方案分工（已对齐）

图数据库只校验已发布的 T-Box，不承担业务数据的问数。问数走业务库里的对象集；冻结图是契约，对象集是数据。推理机把业务术语落到 QueryIntent 并做校验；校不过就停下来或记一条缺口，不要猜着往下走。只有计划校验通过、且确实需要时，才调已发布的 Function / Logic / Action。对外表面是自家的狭窄、形状类似 OMCP 的目录，不是把 Palantir 产品当成自己的对外接口。

4. 记住

推理机不是被 OMCP 取代了，它是问数之前的门禁。目录只暴露已发布且校验通过的能力，避免工具爆炸。
